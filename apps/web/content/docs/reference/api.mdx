Everything you can automate in swarmy goes through one public REST API, served by
your controller at `/api/v1`. It runs on the same service layer and the same
access rules as the dashboard.

## Reference

Your controller serves the API reference itself:

- `https://<controller>/api/v1/docs`: interactive reference.
- `https://<controller>/api/v1/openapi.json`: the OpenAPI document.

The spec is also committed in the repo:
[packages/api-rest/openapi.json](https://github.com/requestflo/swarmy/blob/main/packages/api-rest/openapi.json).

## Authentication

Create an API key under **Settings → API keys**. Send it as a bearer token:

```bash
curl https://<controller>/api/v1/stacks \
  -H "Authorization: Bearer swk_…"
```

A key acts inside one organisation, and the same policies that apply in the
dashboard apply to it.

## Conventions

- JSON is `snake_case`.
- Errors are RFC 9457 `application/problem+json` documents with a
  `swarmy_code`.
- Lists are paginated with a cursor: follow `next_cursor`.
- Send an `Idempotency-Key` header on a POST, PUT, PATCH or DELETE to make a
  retry safe.
- Deploys are asynchronous. Creating, updating (`PATCH /services/{id}`),
  scaling or restarting a service, or deploying a stack, returns `202` with a
  deployment reference you can poll.
- A deploy a guardrail refuses returns `412` with each violation.
- A request refused as invalid returns `400` with `invalid_params`: every
  field it refused (`tls.on_demand`) and why, not just the first.

## Resources

The API covers apps, git connections and repos, stacks, services, nodes, join
tokens, volumes, ingress domains, DNS records, mesh routes, registry
credentials, backups, notifications, the audit log and API keys.

`PATCH /services/{id}` changes a running service: its image, replicas,
command, environment (including secret variables), resources, restart policy,
update order and labels. Send only the fields you want to change. Ports,
volumes, networks and placement can't be changed through it.

Your edge has one settings document, `GET/PUT /ingress/settings`: the
driver, whether it serves, the topology, the Caddy image, pinned nodes, TLS,
a Cloudflare tunnel, a DNS provider for wildcard certificates, the country
database and the base automatic addresses use. A `PUT` sends any subset (left
out keeps, `null` clears), is checked as a whole before anything changes, and
the edge converges once. Writing needs an admin's key.

Join tokens let a new server into the swarm. `POST /join-tokens` (admin only)
returns the token once, with the mesh setup key when your organisation runs a
mesh and the controller URL for the install one-liner. Only a hash is stored,
so a lost token can't be shown again; revoke it with
`DELETE /join-tokens/{id}` and mint another.

## Terraform

The official provider, `requestflo/swarmy`, manages git connections, git repos,
stacks, services, nodes, domains, API keys, join tokens and the edge settings
as Terraform resources, and reads apps and nodes as data sources:

- `swarmy_service` applies an image, env or command change with one
  `PATCH /services/{id}` and waits for it to converge. A guardrail refusal
  fails the apply with each violation.
- `swarmy_join_token` mints a join token, imports one, and revokes it on
  destroy. Changing `label`, `ttl_seconds`, `max_uses` or `profile` replaces
  the token. The token, and the mesh setup key when your organisation runs a
  mesh, are kept as sensitive values in state, with `install_url` for the
  one-liner. A token revoked outside Terraform is recreated on the next apply.
- `swarmy_api_key` refreshes by listing your keys; a key revoked or expired
  outside Terraform is replaced on the next apply.
- `swarmy_ingress` holds your edge settings, one per organisation. Anything
  you leave unset goes back to its default, every apply is one
  `PUT /ingress/settings`, and destroying it resets the settings rather than
  removing the edge. Import it by your organisation id.

```hcl
terraform {
  required_providers {
    swarmy = {
      source = "registry.terraform.io/requestflo/swarmy"
    }
  }
}
```

Source and examples:
[terraform-provider-swarmy](https://github.com/requestflo/swarmy/tree/main/terraform-provider-swarmy).
